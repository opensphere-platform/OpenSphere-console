# Extension Controller

`C_EXT` is a separate Console-native process and service identity. It claims only `console.extension.install@1.0` and `console.extension.revocation.create@1.0` through a fenced PostgreSQL RPC. Revocation remains an atomic authority write. Install re-resolves the approved catalog revision through C_REG, compares the exact image and current `UIPluginPackage` generation/resource version, and creates one idempotent `UIPluginRegistration`; it never creates or rewrites the Package from client input. The apply transaction queues a second fenced observation. C_EXT records `InstallReady` only when the same Package and Registration UID report current generation, exact digest/manifest/source/trust identity, workload `Ready`, supply-chain verification complete, serving `Current`, and revalidation `Passed`.

The runtime login inherits only `console_extension_controller`; it has no direct table mutation grant. Required configuration is `CONSOLE_EXTENSION_DATABASE_URL`. Install execution additionally uses the mounted Kubernetes service-account token and `CONSOLE_REGISTRY_URL`. Optional settings are `CONSOLE_EXTENSION_WORKER_ID`, `CONSOLE_EXTENSION_LEASE_SECONDS`, `CONSOLE_EXTENSION_POLL_MS`, `CONSOLE_EXTENSION_NAMESPACE`, bounded Registry/Kubernetes timeout and response limits, database pool/connect settings, and `PORT`. Kubernetes TLS uses the mounted cluster CA through `NODE_EXTRA_CA_CERTS`.

An install `Applied` receipt proves only `RegistrationPresent`. The later owner observation receipt proves `InstallReady` but leaves the operation `Applied`; Console API independently revalidates the caller and both receipts before `Verified`. Pending, failed, deleted, generation-stale, UID-substituted, Package-replaced, or release-mismatched resources never produce the observation receipt. The existing reconciler continues to own Package/Registration workload convergence. Live Registry connection verification and the write-only credential broker remain later slices. If no Kubernetes service-account token is mounted, revocation remains available while install fails closed before any Kubernetes write or readiness claim.
