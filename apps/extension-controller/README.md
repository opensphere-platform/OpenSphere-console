# Extension Controller

`C_EXT` is a separate Console-native process and service identity. It claims only `console.extension.install@1.0` and `console.extension.revocation.create@1.0` through a fenced PostgreSQL RPC. Revocation remains an atomic authority write. Install re-resolves the approved catalog revision through C_REG, compares the exact image and current `UIPluginPackage` generation/resource version, and creates one idempotent `UIPluginRegistration`; it never creates or rewrites the Package from client input.

The runtime login inherits only `console_extension_controller`; it has no direct table mutation grant. Required configuration is `CONSOLE_EXTENSION_DATABASE_URL`. Install execution additionally uses the mounted Kubernetes service-account token and `CONSOLE_REGISTRY_URL`. Optional settings are `CONSOLE_EXTENSION_WORKER_ID`, `CONSOLE_EXTENSION_LEASE_SECONDS`, `CONSOLE_EXTENSION_POLL_MS`, `CONSOLE_EXTENSION_NAMESPACE`, bounded Registry/Kubernetes timeout and response limits, database pool/connect settings, and `PORT`. Kubernetes TLS uses the mounted cluster CA through `NODE_EXTRA_CA_CERTS`.

An install `Applied` receipt proves `RegistrationPresent`; it does not prove workload readiness or activation. The existing reconciler still owns Package/Registration workload convergence. Independent install observation/verification, live Registry connection verification, and the write-only credential broker remain later slices. If no Kubernetes service-account token is mounted, revocation remains available while install fails closed before any Kubernetes write.
