# Extension Controller

`C_EXT` is a separate Console-native process and service identity. It claims only `console.extension.install@1.0`, `console.extension.remove@1.0`, and `console.extension.revocation.create@1.0` through a fenced PostgreSQL RPC. Revocation remains an atomic authority write. Install re-resolves the approved catalog revision through C_REG, compares the exact image and current `UIPluginPackage` generation/resource version, and creates one idempotent `UIPluginRegistration`; it never creates or rewrites the Package from client input. The apply transaction queues a second fenced observation. C_EXT records `InstallReady` only when the same Package and Registration UID report current generation, exact digest/manifest/source/trust identity, workload `Ready`, supply-chain verification complete, serving `Current`, and revalidation `Passed`.

Removal reads the exact Package and Registration, rejects shell-pinned `main-shell*` scope before any Registration mutation, and applies a merge patch with the current `resourceVersion` precondition to set `spec.desiredState=Uninstalled`. The existing reconciler remains responsible for workload and Registration deletion. C_EXT records `RegistrationAbsent` only when the exact Registration name returns absent after the same UID was captured at apply time; a still-present or replacement UID cannot verify removal.

The runtime login inherits only `console_extension_controller`; it has no direct table mutation grant. Required configuration is `CONSOLE_EXTENSION_DATABASE_URL`. Install execution additionally uses the mounted Kubernetes service-account token and `CONSOLE_REGISTRY_URL`. Optional settings are `CONSOLE_EXTENSION_WORKER_ID`, `CONSOLE_EXTENSION_LEASE_SECONDS`, `CONSOLE_EXTENSION_POLL_MS`, `CONSOLE_EXTENSION_OBSERVATION_MAX_ATTEMPTS` (default 20, allowed 1–100), `CONSOLE_EXTENSION_NAMESPACE`, bounded Registry/Kubernetes timeout and response limits, database pool/connect settings, and `PORT`. Kubernetes TLS uses the mounted cluster CA through `NODE_EXTRA_CA_CERTS`.

An install `Applied` receipt proves only `RegistrationPresent`; a removal `Applied` receipt proves only `RemovalRequested`. The later owner observation receipt proves `InstallReady` or `RegistrationAbsent` but leaves the operation `Applied`; Console API independently revalidates the caller and matching receipts before `Verified`. Pending, failed, generation-stale, UID-substituted, Package-replaced, release-mismatched, or still-present resources never produce a successful observation receipt. The existing reconciler continues to own Package/Registration workload convergence. Live Registry connection verification and the write-only credential broker remain later slices. If no Kubernetes service-account token is mounted, revocation remains available while install and removal fail closed before any Kubernetes write or success claim.

Observation retries reuse the same leased outbox row. Each claim increments its existing `attempt_count`; no scheduler, queue, or retry table is added. Before the configured limit, a pending or transient observation remains retryable after lease expiry. At the limit, C_EXT records `ObservationTimeout` with side effect `unknown`, marks the operation `Unknown`, and delivers the observation outbox. A Kubernetes-reported terminal failure records side effect `present` and marks the operation `Failed`. The default 20-attempt budget is an implementation guard, not an accepted production SLO; environment acceptance must bind it to the lease and expected reconciler convergence time.
