설계·관찰 근거: S13 — 문서 정본의 출처 대장에서 확인

설치 범위를 불필요하게 늘리지 않습니다

  • OpenSphere-Design-Kit은 공통 UI·토큰의 버전 고정 의존성입니다. 별도 상시 Pod나 설치 순번을 만들지 않습니다.
  • CLI·OS Shell·OSAA·Registry·Recovery는 Console 내부 책임입니다. 각각을 별도 제품 설치로 미루지 않습니다.
  • 기존 Kubernetes와 StorageClass로 요구를 충족하면 Ceph·메시·HA를 추가하지 않습니다.
  • Developer·www·다른 설치의 자원은 Console 클린 설치 삭제 범위에 포함하지 않습니다.

게이트를 통과할 때 남기는 기록

  • gateId / 판정(Pass·Fail·NotRun)
  • 검사 시각 / 담당자 / 대상 context·installation ID
  • source revision / Setup version / channel / artifact digest / BOM·migration checksum
  • 검사 분모 / 정상·거절·실패 fixture / 실행 결과
  • 실행 전후 resource inventory / postcondition / receipt·audit correlation
  • rollback·복구 대상 / 잔여 결함 / 다음 진입 허용 여부

설계 근거와 아직 결정할 항목

기존 승인된 제품 경계를 따르는 실행 순서 제안. 문서 작성 요청은 후속 모듈의 설치·삭제·신규 기술 도입 승인이 아니다.

  • Q01 · M03 진입 전 — Cluster Manager의 첫 제한 action, 담당 Owner, API/배포 artifact와 rollback 범위를 확정한다. 읽기 진단이 먼저다.
  • Q02 · M04 진입 전 — 첫 소비자 capability와 provider, 기존 자원 재사용 여부를 정한다. Ceph·HA 등은 요구 근거가 있어야 한다.
  • Q03 · M05 진입 전 — Workforce IdP/issuer/audience, production host, tenant 규모와 최소 앱 하나를 정한다.
  • Q04 · M06–M08 진입 전 — 첫 선택 제품과 profile, SLO/RPO/RTO·데이터 보존·비용·운영 책임을 고정한다.
  • Q05 · 각 게이트 실행 전 — 아직 없는 실행 명령·이미지·namespace를 추정해서 쓰지 않는다. 구현/발행 후 정확한 version/digest와 실행 증거를 기록한다.
  • S1 · Setup 설치 책임 경계 — 2026-09-02 Accepted 책임 구분을 사용. 과거 버전/시험 수치는 현재 상태로 재사용하지 않음.
  • S2 · Console 네이티브 설치 검증 기록 — 로컬 수정·남은 기능/재현 gate의 증거.
  • S3 · 재부팅 후 서비스 복원 점검 — 2026-09-04 00:30–00:36 KST 기동/TLS 관찰. 전체 기능 수용 아님.
  • S4 · Console 실제 DB 격리 복원 증거 — DB 검증 범위만; Storage/Gitea 파일 전체 복원 보증 아님.
  • S5 · Console 설계·네이티브 경계 — 기능별 정본과 수용 Matrix를 링크로 상속.
  • S6 · Cluster Manager 경계 — Observed legacy / Target Proposed. 구체 배포물 미확정.
  • S7 · 첫 종단 운영 여정 JNY-01 — 읽기 진단·승인 작업·receipt 및 실패 흐름의 Proposed 기준.
  • S8 · 첫 릴리스 범위 — Proposed 범위. 사용자 네이티브 완료 요구를 축소하는 근거로 사용하지 않음.
  • S9 · C4 모델 C_CLUSTER / C_FAPI / C_FCTL — Owner/Claim/Binding 의미. 상세 배포 계약이나 현재 구현 완료가 아님.
  • S10 · Workspace 설계 정본 — account/portal/apps 및 독립 제품 launch 경계.
  • S11 · Developer 설계 정본 — standalone/console-hosted profile; 현재 runtime은 S3 참조.
  • S12 · Pulse 설계 정본 — dual mode 및 telemetry/topology/incident 제품 경계.
  • S13 · 제품 domain 대장 — AI Workbench의 제품 경계. 완전 설치 계약으로 보지 않음.
  • S14 · 공식 버전·채널·GHCR 정책 — REL-02 최소 영향, REL-03 버전, REL-04 채널, REL-05 GHCR, digest 고정 기준.
