# Console data migrations

`baseline/0001_console_authority.sql` establishes the first reconstructed fresh-install authority slice: opaque sessions, subject permission/revoke revisions, permission grants, durable operations, independent approvals, transactional outbox, and append-only hash-chained audit records. The constrained `console_api` role has function execution only. `console_operation.accept_operation` atomically writes intent, audit, and outbox; `console_operation.approve_operation` revalidates a distinct AAL2 approver and advances `Planned` to `Authorized` with compare-and-set `state_version`. Verification scripts exercise positive and negative RLS, role isolation, self-approval denial, revocation, stale revision, AAL2, idempotency, atomicity, and audit immutability against a disposable PostgreSQL instance.

`versions/` is reserved for append-only successors with globally unique IDs, predecessor, semantic key, file digest, and migration-set digest. The legacy `backend/supabase/migrations/0001..0073` history remains evidence; new migrations must not extend that sequence. The baseline is still incomplete until the remaining domain tables, complete role/RLS matrix, upgrade fixture, and isolated restore assertions are added.
