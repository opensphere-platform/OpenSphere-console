# Console data migrations

`baseline/0001_console_authority.sql` establishes the first reconstructed fresh-install authority slice: opaque session projection/self-revoke, fail-closed Supabase status projection, subject permission/revoke revisions, permission grants, durable operations, independent approvals, fenced transactional outbox, no-secret Registry connection metadata, minimal non-secret Extension execution plans, install/removal Registration and revocation execution receipts, explicit verification receipts, and append-only hash-chained audit records with bounded cursor reads. The constrained `console_api` and `console_extension_controller` roles have function execution only. Self-revoke rechecks current session revisions and atomically records no-token audit evidence. Intake and approval produce `OperationReadyForDispatch`; owner claim/renew use bounded leases and monotonic epochs. `console_extension.apply_install_registration` binds the stored C_REG plan to observed Package/Registration versions before recording `RegistrationPresent` and queues a bounded observation. `console_extension.apply_remove_registration` binds the exact descriptor, Package, Registration UID/resourceVersion and fenced claim before recording `RemovalRequested` and queuing the removal observation. C_EXT records `InstallReady` only when Package, Registration generation, workload, supply-chain verification, serving and revalidation evidence agree, and records `RegistrationAbsent` only for the same removed UID. Pending observations reuse the same outbox attempt counter. `record_execution_failure` can close either apply or observation dispatch under its current fence: an exhausted observation becomes `Unknown` with side effect `unknown`, while an explicitly terminal owner result becomes `Failed` with side effect `present`; neither advances verification. `console_extension.apply_revocation` atomically records exact-digest revocation. `console_operation.verify_extension_operation` independently revalidates the caller and compares matching C_EXT evidence before moving an install, removal, or revocation operation to `Verified`; callers cannot submit observation evidence. The fixed Registry projection returns configuration and typed verification metadata without credential or SecretRef material. Audit projection requires current `console.audit.read`, caps each newest-first page at 200 and returns chain hashes without adding mutation grants. Verification exercises RLS, role isolation, self-approval denial, shell-pinned removal denial, revocation, stale revision, AAL2, idempotency, concurrent/expired claims, stale fencing, target or UID substitution, install plan binding, bounded observation failure, observation mismatch, atomicity, pagination, and audit continuity against a disposable PostgreSQL instance.

`versions/` is reserved for append-only successors with globally unique IDs, predecessor, semantic key, file digest, and migration-set digest. The legacy `backend/supabase/migrations/0001..0073` history remains evidence; new migrations must not extend that sequence. The baseline is still incomplete until the remaining domain tables, complete role/RLS matrix, upgrade fixture, and isolated restore assertions are added.
